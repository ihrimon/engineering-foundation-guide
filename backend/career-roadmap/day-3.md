## Common Path

### Disclaimer

Assumptions for this timeline:

- You are starting from scratch.
- You will learn 7 days a week.
- You will spend at least 4–5 hours a day.
- You have a general understanding level.
- You have prior experience using a computer, but not in development.

### Timeline

**1. Programming — target 4–6 months**
- Pick your favourite language.
- Cover all fundamental concepts.
- Try to solve practice problems.

**2. Internet — target 2–3 weeks**
- What is the internet?
- What is HTTP?
- What is a browser?
- What is DNS?
- What is a server?
- How do these things work together?

**3. Framework — target 2 months**
- Pick your favourite framework.
- Understand the fundamentals.
- Explore the provided features.
- Create 4–5 practice projects.

**4. Database — target 1–2 months**
- Cover the basics for now.
- Pick a relational database.
- Learn database schema design.
- Learn basic normalization, basic queries, and joins.
- Learn a good ORM for your framework.

**5. Git — target 2–4 weeks**
- Get comfortable with common Git commands.
- Start using GitHub.
- Learn issues, pull requests, and forking.

**6. API Design — target 1–2 months**
- REST API constraints.
- REST API design, documentation & testing.
- Learn OAuth and API security.
- Scalable API design that follows best practices.

**7. Integration — target 1–2 months**
- Explore a lot of third-party services.
- Explore their REST APIs.
- Try to integrate as many services as you can.

**8. Cloud — target 1–2 months**
- How to SSH to a remote server.
- Basic Linux commands.
- Run your application on the server.
- You can skip this and use services like Netlify or Vercel.

### Congratulations!

### Achievements

- Now you are eligible for a junior backend role.
- However, this doesn't guarantee you'll crack the interview.
- Only small startups will likely give you a chance.
- Salary range will be low to moderate.
- In backend, salary comes with experience.

## Career Path

*For dreamers & hard workers.*

### Job Roles to Explore First

**Core Backend Development**
- Junior Backend Developer — builds basic APIs and implements core functionalities.
- Backend Developer — creates and maintains web applications, focusing on server-side logic.
- Full-Stack Developer — works on both front-end and back-end development.
- API Developer — designs and develops APIs for data access.
- Microservices Developer — builds small, independent services that work together.
- Backend Test Engineer — writes and executes automated tests.
- Security Engineer (Backend) — implements security measures for backend applications and data.

**Data Management**
- Database Administrator (DBA) — manages and optimizes databases.
- Database Engineer — designs, builds, and maintains database infrastructures.
- Data Architect — creates data models and strategies for storage and retrieval.
- ETL Developer — extracts, transforms, and loads data between sources.

**Backend & System Integration**
- Software Architect — designs overall software architecture (scalability, security, maintainability).
- System Designer — creates blueprints for backend systems.
- Integration Specialist — integrates backend systems with third-party applications.
- Backend Performance Engineer — optimizes backend applications for speed and efficiency.

**DevOps & Cloud Management**
- DevOps Engineer — bridges development and operations, automates workflows.
- Site Reliability Engineer (SRE) — ensures reliability and scalability of backend systems.
- Cloud Architect — designs cloud-based solutions for backend infrastructure.
- Cloud Engineer — provisions and manages cloud resources.

## Job Interview & Preparation

### Structure of a Technical Job Interview

There's no rock-solid structure — it depends on the company and its culture. Some companies focus on technical expertise, others on soft skills.

Common stages:

- Communication Test
- Online Coding Test
- Technical Interview
- Take Home Project
- Project Review
- Cultural Test

### Interview Preparation

- Data Structures & Algorithms
- Solve at least 500 problems on LeetCode
- System design case studies
- Common database problems & solutions
